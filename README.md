# 循码 · Guided Learning Assistant

面向大学程序设计公共课的引导式学习助教第一版原型。它不直接代替学生作答，而是通过“核心讲解 → 运行预测 → 错误诊断 → 多维评价”帮助学生真正读懂代码。

## 为什么做这个项目

生成一段正确代码很容易，但初学者真正困难的是：

- 不知道每一行为什么存在；
- 看不出边界、初始化、返回值等隐蔽错误；
- 答对后也说不清原因；
- 教师只能看到最终答案，看不到学生卡在哪里。

循码把学习过程结构化，并为教师留下可观察的过程证据。

## 已完成的 MVP

- 4 个 C++ 学习单元：循环、分支、数组、函数；
- 正确代码与故意错误代码双模式；
- 输出预测与代码诊断；
- 正确性、表达规范、分析深度、反问质量四维评价；
- 错误后的下一步学习建议；
- 教师观察台、能力画像、学习信号与 JSON 记录导出；
- 本地持久化，不上传学生回答；
- 评价引擎单元测试与 GitHub Actions。

## 本地运行

```bash
cd guided-learning-assistant
python3 -m http.server 4173
```

浏览器打开 `http://localhost:4173`。

运行测试：

```bash
npm test
```

## 技术设计

- `src/content.js`：可配置的知识单元与错误案例；
- `src/evaluator.js`：可测试、可解释的形成性评价引擎；
- `src/app.js`：学习状态机、过程记录、教师端聚合与导出；
- `localStorage`：第一版隐私友好的本地学习记录。

当前评分是透明的规则化原型，不假装是真实 AI。下一版可以在保持量表约束和教师可审计的前提下接入校内知识库或大模型。

## 下一阶段

1. 与真实课程知识图谱连接，支持教师导入知识点和题目；
2. 加入分层提示策略，答错时逐步缩小问题；
3. 接入受约束的 LLM 评价，并与人工评分做一致性验证；
4. 增加班级视图、错误类型分布和学习路径实验；
5. 进行小规模学生可用性测试，比较“直接答案”和“引导式学习”的效果。

## 隐私与教学原则

- 不把分数用于学生排名；
- 评价必须展示依据与改进方向；
- 学生可查看、导出和删除自己的记录；
- AI 建议不代替教师最终判断。
